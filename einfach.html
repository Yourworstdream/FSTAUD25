Erst mal: 7 neue Wörter

Auf GitHub ist fast alles auf Englisch. Diese 7 Wörter reichen für den Anfang:

📁
RepositoryUnser gemeinsamer Klassen-Ordner im Internet. Da liegen alle Dateien.
📌
IssueEin Zettel an der Pinnwand: eine Frage, eine Aufgabe oder eine Idee.
🌿
BranchDeine eigene Kopie zum Ausprobieren. Das Original bleibt heil.
💾
CommitSpeichern. Dazu schreibst du einen kurzen Satz, was du geändert hast.
📬
Pull RequestDu fragst: „Darf meine Änderung ins Original?“
👀
ReviewJemand aus der Klasse schaut drüber und sagt: „Passt!“
✅
MergeDeine Änderung kommt ins Original. Fertig!

🌿 Kopie → 💾 Speichern → 📬 Fragen → 👀 Prüfen → ✅ Übernehmen

Das ist immer derselbe Ablauf. Wenn du ihn einmal gemacht hast, kannst du ihn.

Das brauchst du

  • 📱Handy oder Laptop (Laptop ist bequemer)
  • 📧Deine E-Mail-Adresse und Zugriff auf dein Postfach
  • 🤝Einen Partner aus der Klasse Ihr prüft euch gegenseitig
  • ⏱️Etwa 30 Minuten

🔑 Vorbereitung

GitHub-Konto erstellen

Darum geht's: Ohne Konto kannst du nicht mitmachen. Das Konto ist kostenlos.

  1. Öffne github.com/signup ↗.
  2. Trag deine E-Mail-Adresse und ein Passwort ein.
  3. Denk dir einen Benutzernamen aus. Das ist dein Name auf GitHub. Erlaubt sind Buchstaben, Zahlen und Bindestriche.
    ✏️ Schreib dir den Benutzernamen auf! Du brauchst ihn gleich.
  4. Klick auf Continue bzw. Create account.
  5. Löse das kleine Bilder-Rätsel.
  6. Schau in dein E-Mail-Postfach. GitHub schickt dir einen Code. Tipp ihn ein.
  7. Wenn GitHub Fragen stellt: Du kannst sie überspringen (Skip). Wenn es nach einem Plan fragt: Nimm Free (kostenlos).

✅ Fertig, wenn du oben rechts auf GitHub dein Profilbild siehst.

🔒 Gut zu wissen: Irgendwann will GitHub einen Zusatz-Schutz (Zwei-Faktor, „2FA“). Dafür brauchst du eine App auf dem Handy, z. B. Microsoft Authenticator oder Google Authenticator. Folge einfach den Anweisungen: QR-Code scannen, Zahl eintippen. Die Notfall-Codes (recovery codes) gut aufheben!
😕 Klappt nicht?
  • Keine E-Mail da? Schau im Spam-Ordner nach.
  • Benutzername schon vergeben? Nimm einen anderen, z. B. mit einer Zahl dahinter.

📝 Meilenstein „Angemeldet“

Für die Klasse anmelden

Darum geht's: So weiß @Yourworstdream, dass du mitmachst, und kann dich einladen.

  1. Klick hier: 📝 Zum Anmelde-Formular
  2. Schreib deinen Vornamen und den ersten Buchstaben vom Nachnamen. Beispiel: Max M.
  3. Schreib deinen GitHub-Benutzernamen dazu.
  4. Klick auf Anmeldung auf GitHub öffnen ↗.
  5. GitHub geht auf. Alles ist schon ausgefüllt. Hake das Kästchen bei den Teamregeln an.
  6. Klick unten auf den grünen Knopf Create.

✅ Fertig, wenn du die Seite „Anmeldung: Dein Name“ siehst. Auf dem Live-Fortschritt erscheint deine Karte mit 📝.

⚠️ Wichtig: Das Repository ist öffentlich. Jeder im Internet kann es lesen. Darum nur Vorname + ein Buchstabe. Keine Adresse, keine Telefonnummer.
2
🤝 Meilenstein „Im Team“

Einladung annehmen

Darum geht's: Erst mit der Einladung darfst du im Klassen-Ordner mitarbeiten.

  1. Warte kurz. @Yourworstdream lädt dich ein. Das kann ein paar Minuten dauern.
  2. Schau in dein E-Mail-Postfach. Die E-Mail heißt ungefähr so: „@Yourworstdream has invited you to collaborate on the Yourworstdream/FSTAUD25 repository“.
  3. Klick in der E-Mail auf View invitation.
  4. Klick auf den grünen Knopf Accept invitation.

Keine E-Mail? Öffne direkt: Einladung auf GitHub ↗

✅ Fertig, wenn du die Dateien vom Klassen-Ordner siehst. Dein Anmelde-Zettel schließt sich dann von selbst.

😕 Klappt nicht?
  • GitHub zeigt dir einen Knopf Fork? Nicht klicken! Dann hast du die Einladung noch nicht angenommen.
  • „Invitation not found“? Dann bist du noch nicht eingeladen. Sag @Yourworstdream Bescheid.
3
🌿 Meilenstein „Pull Request“

Deinen Steckbrief schreiben

Darum geht's: Du machst zum ersten Mal den ganzen Ablauf: Kopie 🌿 → Speichern 💾 → Fragen 📬. Dein Steckbrief ist eine kleine Datei über dich.

  1. Schreib oben deinen Benutzernamen und deinen Namen hinein.
  2. Klick hier: 📄 Meinen Steckbrief öffnen ↗
    GitHub macht eine neue Datei auf. Name und Text sind schon drin.
  3. Öffne den Klassen-Ordner: github.com/Yourworstdream/FSTAUD25. Klick auf den Ordner teilnehmer.
    Einfacher geht's auf der Webseite (QR-Code oben): Dort füllt ein Knopf alles für dich aus.
  4. Klick auf Add file → Create new file.
  5. Als Dateiname schreibst du deinen Benutzernamen mit .md am Ende, z. B. max-m.md. In die Datei kommt: 
    # Max M.

- **Emoji:** 🤖
- **Das will ich lernen:** Mit Git und GitHub im Team arbeiten
- **Lieblingsthema in der Automatisierung:** SPS-Programmierung
  6. Ändere den Text so, wie du willst: dein Name, dein Emoji, was du lernen willst, dein Lieblingsthema.
  7. Klick oben rechts auf den grünen Knopf Commit changes….
  8. Ein Fenster geht auf. Wähle unten:
    ◉ Create a new branch for this commit and start a pull request
  9. Klick auf Propose changes.
  10. Eine neue Seite geht auf. Rechts steht Reviewers. Klick dort auf das Zahnrad ⚙️ und such deinen Partner aus.
  11. Klick auf den grünen Knopf Create pull request.

✅ Fertig, wenn oben ein grünes Open steht. Auf dem Live-Fortschritt leuchtet 🌿.

😕 Klappt nicht?
  • Da steht Fork this repository? Dann fehlt Schritt 2 (Einladung annehmen).
  • Der Dateiname muss genau dein Benutzername sein, mit .md am Ende. Beispiel: max-m.md
4
✅ Meilenstein „Gemerged“

Prüfen lassen und übernehmen

Darum geht's: Bevor etwas ins Original kommt, schaut eine zweite Person drüber. Danach übernimmst du deine Änderung (Merge).

  1. Sag deinem Partner: „Kannst du meinen Pull Request prüfen?“ (Dein Partner macht dafür Schritt 5.)
  2. Warte, bis dein Partner Approve gegeben hat. Das heißt: „Passt!“ Du siehst dann ein grünes Häkchen ✔ mit approved.
  3. Öffne deinen Pull Request: oben auf Pull requests klicken und dann deinen anklicken.
  4. Scroll ganz nach unten. Klick auf Merge pull request.
  5. Klick auf Confirm merge.
  6. Klick auf Delete branch. Die Kopie brauchst du nicht mehr.

✅ Fertig, wenn oben ein lila Merged steht. 🎉 Auf dem Live-Fortschritt leuchtet ✅.

😕 Klappt nicht?
  • Der Merge-Knopf ist grau? Dann fehlt noch das Approve von deinem Partner.
  • Dein Partner will, dass du etwas änderst (Changes requested)? Im Pull Request auf Files changed → bei deiner Datei auf ⋯ → Edit file. Ändern, dann Commit changes…. Der Pull Request passt sich von selbst an.
5
👀 Meilenstein „Review“

Selbst prüfen

Darum geht's: Jetzt bist du der Prüfer für deinen Partner. Vier Augen sehen mehr als zwei.

  1. Oben auf Pull requests klicken. Den Pull Request von deinem Partner anklicken.
  2. Klick auf Files changed. Grün heißt: neu. Rot heißt: gelöscht.
  3. Lies alles in Ruhe. Stimmt der Dateiname? Gibt es Tippfehler?
  4. Klick oben rechts auf den grünen Knopf Review changes. Bei manchen heißt er Submit review.
  5. Schreib einen netten Satz. Beispiel: „Sieht gut aus! 👍“
  6. Wähle ◉ Approve und klick auf Submit review.

✅ Fertig, wenn im Pull Request steht: „dein-name approved these changes“. Auf dem Live-Fortschritt leuchtet 👀.

🤝 Regel: Immer freundlich. Erst loben, dann Tipps geben. Sag genau, was du meinst, z. B. „In Zeile 3 fehlt ein Buchstabe.“
6
💬 Meilenstein „Diskussion“

Mitreden

Darum geht's: In den Issues (Pinnwand-Zetteln) reden wir über Aufgaben und Ideen.

  1. Oben auf Issues ↗ klicken.
  2. Ein Thema anklicken, z. B. „Thema 03: Sensoren in der Automatisierung“.
  3. Ganz unten ins Textfeld schreiben. Beispiel: „Spannend! Induktive Sensoren kenne ich aus dem Betrieb.“
  4. Klick auf Comment.

✅ Fertig, wenn dein Kommentar unter dem Thema steht. Auf dem Live-Fortschritt leuchtet 💬.

💡 Trick: Schreib @ und einen Benutzernamen, z. B. @max-m. Dann bekommt die Person eine Nachricht.
7
🚀 Meilenstein „Projekt“

Eine Wiki-Seite schreiben

Darum geht's: Zusammen schreiben wir ein Nachschlagewerk zur Automatisierungstechnik. 12 Themen für 12 Leute. Du schreibst eine Seite.

  1. Öffne die Themen-Liste ↗. Such dir ein Thema aus, das noch frei ist (rechts noch kein Profilbild).
  2. Öffne das Thema. Schreib als Kommentar: „Ich übernehme das“ und klick auf Comment.
  3. Rechts bei Assignees auf assign yourself klicken. Jetzt ist es dein Thema.
  4. Im Thema steht genau, was auf deine Seite gehört. Klick dort auf 📄 Datei … anlegen ↗.
  5. Kopiere den Text aus der Vorlage ↗ hinein und schreib deine Seite.
  6. Jetzt wie bei Schritt 3: Commit changes… → ◉ Create a new branch … → Propose changes → Partner bei Reviewers eintragen. In die Beschreibung schreibst du Closes # und die Nummer von deinem Thema (steht im Thema). Dann Create pull request.
  7. Jetzt wie bei Schritt 4: Prüfen lassen und Merge pull request.

✅ Fertig, wenn deine Seite gemerged ist. Auf dem Live-Fortschritt leuchtet 🚀. Du hast alle 7 Meilensteine geschafft! 🏆

🆘 Hilfe! Es klappt nicht

Ich finde einen Knopf nicht.
Am Handy sind manche Knöpfe versteckt. Dreh das Handy quer oder nimm den Laptop.
Ich habe etwas falsch gemacht.
Keine Panik! Git merkt sich jeden alten Stand. Es geht nichts verloren. Frag einfach nach.
Da steht „Conflict“.
Zwei Leute haben dieselbe Zeile geändert. Das ist normal. Hol dir Hilfe oder lies Merge-Konflikte lösen.
Ich komme gar nicht weiter.
Frag deinen Nachbarn oder @Yourworstdream. Oder schreib ein 🆘 Hilfe-Issue ↗. Dann hilft dir die Klasse.
