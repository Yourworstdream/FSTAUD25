GitHub-Anleitung für die FST AUD 25

Online mit allen Links und dem Anmeldeformular:
yourworstdream.github.io/FSTAUD25

Wir arbeiten dieses Schuljahr gemeinsam in einem GitHub-Repository. Diese Seite bringt dich in sieben Schritten dorthin. Du brauchst nur einen Browser, rechne mit etwa 30 Minuten. Am besten suchst du dir einen Partner aus der Klasse, ihr prüft euch in Schritt 4 und 5 gegenseitig.

  1. Konto erstellen und anmelden
  2. Einladung annehmen
  3. Steckbrief vorschlagen
  4. Review abwarten und mergen
  5. Einen Pull Request prüfen
  6. In einem Issue mitreden
  7. Eine Wiki-Seite schreiben

Du bist als @ eingetragen.

Schritt 1 von 7

Konto erstellen und anmelden

Falls du noch kein GitHub-Konto hast, registriere dich auf github.com/signup. Merk dir deinen Benutzernamen. GitHub verlangt eine Zwei-Faktor-Anmeldung, das geht am einfachsten mit einer Authenticator-App auf dem Handy.

Dann trägst du dich hier ein. Danach öffnet sich GitHub mit einem fertig ausgefüllten Formular, dort klickst du nur noch auf Create.

Das Formular dazu findest du auf der Online-Seite (QR-Code oben).

GitHub wurde in einem neuen Tab geöffnet. Klick dort auf Create, dann bist du angemeldet. Kein neuer Tab? Formular hier öffnen.

Das Repository ist öffentlich. Deshalb bitte nur Vorname und Anfangsbuchstabe.

Fertig, wenn du auf GitHub die Seite „Anmeldung: dein Name“ siehst.

Schritt 2 von 7

Einladung annehmen

Nach deiner Anmeldung lädt dich @Yourworstdream ins Repository ein. Du bekommst dazu eine E-Mail von GitHub. Schau auch im Spam-Ordner nach.

Klick in der E-Mail auf View invitation und dann auf Accept invitation. Du kannst die Einladung auch direkt hier öffnen. Sie gilt 7 Tage.

Fertig, wenn du nach dem Klick auf Accept invitation im Repository landest. Bietet dir GitHub später an, das Repository zu „forken“, ist die Einladung noch nicht angenommen.

Schritt 3 von 7

Steckbrief vorschlagen

Am Hauptstand des Projekts (main) ändert niemand direkt etwas. Du machst deine Änderung auf einem eigenen Zweig, einem Branch, und schlägst sie dann vor. Dieser Vorschlag heißt Pull Request.

  1. Öffne die vorbereitete Datei: Steckbrief anlegen. Name und Text sind schon eingetragen, du kannst den Text noch ändern.
  2. Klick auf Commit changes.
  3. Wähle Create a new branch for this commit and start a pull request und klick auf Propose changes.
  4. Wähl rechts bei Reviewers eine Person aus der Klasse aus und klick auf Create pull request.

Die Datei muss genauso heißen wie dein Benutzername, also benutzername.md. Trag in Schritt 1 deinen Namen ein, dann stimmt das automatisch.

Fertig, wenn oben im Pull Request ein grünes „Open“ steht.

Schritt 4 von 7

Review abwarten und mergen

Jetzt schaut sich eine andere Person deinen Pull Request an. Gibt sie ihn frei (Approve), klickst du unten auf Merge pull request und dann auf Confirm merge. Damit ist deine Änderung im Hauptstand. Den Branch kannst du danach mit Delete branch löschen.

Soll noch etwas geändert werden, bearbeite die Datei direkt im Pull Request unter Files changed. Einen neuen Pull Request brauchst du dafür nicht.

Fertig, wenn oben ein lila „Merged“ steht. Ist der Merge-Knopf grau, fehlt noch die Freigabe.

Schritt 5 von 7

Einen Pull Request prüfen

Öffne einen offenen Pull Request von jemand anderem. Unter Files changed siehst du, was geändert wurde: Grün ist neu, Rot wurde gelöscht.

Klick oben rechts auf Review changes, wähle Approve, wenn alles passt, oder Request changes, wenn etwas fehlt, und schreib kurz dazu, warum. Bleib dabei freundlich und konkret.

Fertig, wenn im Pull Request „dein-name approved these changes“ steht.

Schritt 6 von 7

In einem Issue mitreden

Issues sind unsere Aufgabenliste. Öffne eines der Themen fürs Wiki und schreib unten einen Kommentar, zum Beispiel welches Thema dich interessiert.

Fertig, wenn dein Kommentar unter dem Issue steht.

Schritt 7 von 7

Eine Wiki-Seite schreiben

Zusammen schreiben wir ein kleines Wiki zur Automatisierungstechnik. Es gibt 12 Themen, jede Person übernimmt eins.

  1. Such dir bei den Themen ein freies aus, schreib „Ich übernehme das“ und trag dich rechts bei Assignees ein.
  2. Klick im Themen-Issue auf den Link zum Anlegen der Datei, der Dateiname ist dort schon eingetragen. Den Text kopierst du aus der Vorlage, die im Issue verlinkt ist.
  3. Weiter wie in Schritt 3 und 4: neuer Branch, Pull Request, Review, Merge. Schreib in den Pull Request Closes # und die Nummer deines Themen-Issues.

Fertig, wenn dein Pull Request mit der Wiki-Seite gemerged ist.

Das war's. Wenn du irgendwo hängst, schau auf die Hilfe-Seite oder frag in der Klasse.
