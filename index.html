Online mit allen Links und dem Anmeldeformular:
yourworstdream.github.io/FSTAUD25

Wir arbeiten dieses Schuljahr gemeinsam in einem GitHub-Repository. Diese Seite bringt dich in sieben Schritten dorthin. Du brauchst nur einen Browser und ein bis zwei Stunden. Such dir einen Partner aus der Klasse, ihr prüft euch in Schritt 4 und 5 gegenseitig. GitHub ist auf Englisch: Die Namen der Knöpfe stehen hier fett, genau so wie auf GitHub.

So funktioniert GitHub

Ein Repository ist ein Projektordner, der sich jede Änderung merkt. Der geprüfte Stand darin heißt main. Wer etwas ändern will, arbeitet auf einem eigenen Zweig, einem Branch, und speichert dort mit einem Commit. Mit einem Pull Request schlägt man die Änderung vor. Eine zweite Person prüft sie, das ist das Review. Danach wird sie in main übernommen, das ist der Merge.

Diesen Ablauf machst du heute zweimal: erst mit einem Steckbrief, dann mit einer Wiki-Seite.

  1. Konto erstellen und anmelden
  2. Einladung annehmen
  3. Steckbrief vorschlagen
  4. Review abwarten und mergen
  5. Einen Pull Request prüfen
  6. In einem Issue mitreden
  7. Eine Wiki-Seite schreiben

Du bist als @ eingetragen.

Schritt 1 von 7 · etwa 10 Minuten

Konto erstellen und anmelden

Falls du noch kein GitHub-Konto hast, registriere dich auf github.com/signup. Merk dir deinen Benutzernamen. Fragt GitHub nach einer Zwei-Faktor-Anmeldung, kannst du das heute überspringen und in den nächsten Tagen einrichten.

Dann trägst du dich hier ein. Danach öffnet sich GitHub mit einem ausgefüllten Formular. Dort setzt du den Haken bei den Regeln und klickst auf Create. So entsteht dein Anmelde-Issue. Ein Issue ist auf GitHub ein Eintrag in der Aufgabenliste.

Das Formular dazu findest du auf der Online-Seite (QR-Code oben).

GitHub wurde in einem neuen Tab geöffnet. Setz dort den Haken bei den Regeln und klick auf Create, dann bist du angemeldet. Kein neuer Tab? Formular hier öffnen.

Das Repository ist öffentlich. Deshalb bitte nur Vorname und Anfangsbuchstabe.

Fertig, wenn du auf GitHub die Seite „Anmeldung: dein Name“ siehst.

Schritt 2 von 7 · etwa 5 Minuten

Einladung annehmen

Nach deiner Anmeldung lädt dich @Yourworstdream ins Repository ein. Du bekommst dazu eine E-Mail von GitHub. Schau auch im Spam-Ordner nach.

Klick in der E-Mail auf View invitation und dann auf Accept invitation. Du kannst die Einladung auch direkt hier öffnen. Sie gilt 7 Tage.

Solange du wartest, steht in der Klassenliste hinter deinem Namen „wartet auf Einladung“.

Schreib danach in dein Anmelde-Issue kurz „angenommen“. Dann wird es geschlossen und dein Häkchen erscheint gleich in der Klassenliste.

Fertig, wenn dein Anmelde-Issue geschlossen ist. Bietet dir GitHub an, das Repository zu „forken“ (eine eigene Kopie anzulegen), ist die Einladung noch nicht angenommen.

Schritt 3 von 7 · etwa 10 Minuten

Steckbrief vorschlagen

Am Hauptstand des Projekts (main) ändert niemand direkt etwas. Du machst deine Änderung auf einem eigenen Zweig, einem Branch, und schlägst sie dann vor. Dieser Vorschlag heißt Pull Request.

  1. Öffne die vorbereitete Datei: Steckbrief anlegen. Name und Text sind schon eingetragen, du kannst den Text noch ändern.
  2. Klick auf Commit changes.
  3. Wähle Create a new branch for this commit and start a pull request und klick auf Propose changes.
  4. Wähle rechts bei Reviewers deinen Partner aus und klick auf Create pull request.

Die Datei muss genauso heißen wie dein Benutzername, also benutzername.md. Trag in Schritt 1 deinen Benutzernamen ein, dann stimmt das automatisch.

Fertig, wenn oben im Pull Request ein grünes „Open“ steht.

Schritt 4 von 7 · etwa 10 Minuten

Review abwarten und mergen

Jetzt schaut sich eine andere Person deinen Pull Request an, am besten dein Partner. In der Klassenliste steht bei dir so lange „wartet auf Review“. Gibt sie ihn frei (Approve), klickst du unten auf Merge pull request und dann auf Confirm merge. Damit ist deine Änderung im Hauptstand. Den Branch kannst du danach mit Delete branch löschen.

Soll noch etwas geändert werden, bearbeite die Datei direkt im Pull Request: Files changed, bei der Datei auf die drei Punkte, dann Edit file. Einen neuen Pull Request brauchst du dafür nicht.

Fertig, wenn oben ein lila „Merged“ steht. Ist der Merge-Knopf grau, fehlt noch die Freigabe.

Schritt 5 von 7 · etwa 5 Minuten

Einen Pull Request prüfen

Öffne einen offenen Pull Request von jemand anderem. Wer gerade auf ein Review wartet, steht in der Klassenliste unter „Jetzt zu tun“. Unter Files changed siehst du, was geändert wurde: Grün ist neu, Rot wurde gelöscht.

Klick oben rechts auf Review changes, wähle Approve, wenn alles passt, oder Request changes, wenn etwas fehlt, und schreib kurz dazu, warum. Bleib dabei freundlich und konkret.

Fertig, wenn im Pull Request dein Benutzername und „approved these changes“ steht.

Schritt 6 von 7 · etwa 5 Minuten

In einem Issue mitreden

Issues sind unsere Aufgabenliste. Öffne eines der Themen fürs Wiki und schreib unten einen Kommentar, zum Beispiel welches Thema dich interessiert.

Fertig, wenn dein Kommentar unter dem Issue steht.

Schritt 7 von 7 · etwa 20 Minuten

Eine Wiki-Seite schreiben

Zusammen schreiben wir ein kleines Wiki zur Automatisierungstechnik. Es gibt 12 Themen, jede Person übernimmt eins. Die Seiten sind Dateien im Ordner projekt/themen. Für heute reichen drei Sätze unter „Worum geht es?“. Ausbauen kannst du die Seite später, wieder mit Branch und Pull Request.

  1. Such dir bei den Themen ein freies aus, schreib „Ich übernehme das“ und trag dich rechts bei Assignees ein.
  2. Klick im Themen-Issue auf den Link zum Anlegen der Datei, der Dateiname ist dort schon eingetragen. Öffne die Vorlage, die im Issue verlinkt ist, kopiere ihren Text mit Copy raw file und füg ihn in die neue Datei ein.
  3. Weiter wie in Schritt 3 und 4: neuer Branch, Pull Request, Review, Merge. Schreib in den Pull Request Closes # und die Nummer deines Themen-Issues.

Fertig, wenn dein Pull Request mit der Wiki-Seite gemerged ist.

Das war's. Zum Schluss kannst du mit sechs kurzen Fragen prüfen, ob alles sitzt.

Wenn du irgendwo hängst, schau auf die Hilfe-Seite, frag deinen Partner oder schreib ein Hilfe-Issue. Das erscheint dann in der Klassenliste.
