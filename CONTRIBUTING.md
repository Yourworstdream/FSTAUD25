# Teamregeln der FST AUD 25

Damit zwölf Leute gleichzeitig an einem Repository arbeiten können, halten wir uns an ein paar einfache Regeln.

1. **Nie direkt auf `main`.** Jede Änderung läuft über einen eigenen Branch und einen Pull Request.
2. **Ein Branch = ein Thema.** Kleine Pull Requests werden schneller geprüft und machen weniger Konflikte.
3. **Gute Commit-Nachrichten.** Schreib, *was* sich geändert hat: `Sensoren: Abschnitt zu induktiven Sensoren ergänzt` statt `update`.
4. **Vorher aktualisieren.** Vor dem Start den neuesten Stand von `main` holen (im PR: „Update branch“).
5. **Nur eigene Dateien bearbeiten** – außer es ist abgesprochen.
6. **Respektvolle Reviews.** Sachlich, konkret und freundlich. Kritisiere die Sache, nie die Person.
7. **Keine Passwörter oder privaten Daten.** Das Repository ist öffentlich.
8. **Nach dem Merge** den Branch löschen.

## Der Ablauf (GitHub Flow)

```
Issue  →  Branch  →  Commits  →  Pull Request  →  Review  →  Merge
```

## Branch-Namen

Kurz, klein geschrieben, mit Bindestrichen:

- `steckbrief-max-m` – dein Steckbrief
- `thema/03-sensoren` – eine Wiki-Seite
- `fix/tippfehler-sps` – eine Korrektur

Die ausführliche Anleitung mit allen Klicks findest du unter https://yourworstdream.github.io/FSTAUD25/.
