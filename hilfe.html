Anleitung Fortschritt Hilfe GitHub

Hilfe

Hier steht alles zum Nachschlagen. Du musst das nicht durchlesen, um mitzumachen. Wenn du nicht weiterkommst, frag in der Klasse oder schreib ein Hilfe-Issue.

Häufige Probleme

Ich habe keine Einladung bekommen.

Schau im Spam-Ordner nach oder öffne direkt die Einladungsseite. Steht dort nichts, wurdest du noch nicht eingeladen. Prüf dann, ob deine Anmeldung bei den Anmeldungen auftaucht.

GitHub will, dass ich das Repository „forke“.

Dann hast du die Einladung noch nicht angenommen (Schritt 2). Nicht forken, sondern erst die Einladung annehmen und die Seite neu laden.

Ich kann nicht mergen, da steht „Review required“.

Das ist so gewollt. Erst muss eine andere Person deinen Pull Request mit Approve freigeben.

Ich habe einen Fehler im Pull Request.

Kein Problem. Öffne im Pull Request Files changed, klick bei der Datei auf die drei Punkte und dann auf Edit file. Speicher die Änderung im selben Branch. Der Pull Request aktualisiert sich von selbst.

Ich habe aus Versehen etwas Falsches gemerged.

Bei Git geht nichts verloren. Im gemergten Pull Request gibt es unten den Knopf Revert. Er erstellt einen neuen Pull Request, der die Änderung rückgängig macht.

Mein Häkchen in der Klassenliste fehlt.

Die Liste aktualisiert sich etwa eine Minute nach jeder Aktion auf GitHub. Nur das Annehmen der Einladung meldet GitHub nicht sofort: Dieses Häkchen erscheint spätestens, wenn du deinen ersten Pull Request öffnest. Prüf außerdem, ob deine Steckbrief-Datei genauso heißt wie dein Benutzername.

Da steht „This branch has conflicts“.

Siehe Merge-Konflikt lösen weiter unten.

Begriffe

Repository
Der Projektordner mit allen Dateien und ihrer ganzen Geschichte.
Commit
Ein gespeicherter Zwischenstand mit einer kurzen Beschreibung.
Branch
Ein eigener Zweig, auf dem du arbeitest, ohne den Hauptstand zu verändern.
main
Der Hauptstand. Hier landet nur, was geprüft wurde.
Pull Request
Der Vorschlag, die Änderungen aus deinem Branch in main zu übernehmen.
Review
Eine andere Person prüft deinen Pull Request.
Merge
Das Übernehmen eines Branches in main.
Issue
Ein Eintrag in der Aufgabenliste: Frage, Idee, Fehler oder Thema.

Unsere Regeln

  1. Nie direkt auf main arbeiten, immer Branch und Pull Request.
  2. Ein Branch für ein Thema. Kleine Pull Requests sind schneller geprüft.
  3. Commit-Nachrichten sagen, was sich geändert hat, also „Tippfehler in der PID-Formel korrigiert“ statt „update“.
  4. Nur eigene Dateien bearbeiten, außer es ist abgesprochen.
  5. Reviews sind freundlich und konkret.
  6. Keine Passwörter oder privaten Daten ins Repository, es ist öffentlich.

Merge-Konflikt lösen

Ein Konflikt entsteht, wenn zwei Leute dieselbe Stelle einer Datei unterschiedlich geändert haben. Git weiß dann nicht, welche Version stimmt, und markiert die Stelle so:

<<<<<<< thema/03-sensoren
| 03 | Sensoren | Jonas M. |
=======
| 03 | Sensoren | Aylin S. |
>>>>>>> main
  1. Klick im Pull Request auf Resolve conflicts.
  2. Lösch die drei Markierungszeilen (<<<, ===, >>>) und lass stehen, was richtig ist. Manchmal sind das beide Zeilen.
  3. Klick auf Mark as resolved und dann auf Commit merge.

Mit Git auf dem eigenen PC

Das ist freiwillig, für die Schritte reicht der Browser. Am einfachsten geht es mit GitHub Desktop. Wer die Kommandozeile mag, installiert Git und arbeitet so:

git clone https://github.com/Yourworstdream/FSTAUD25.git
cd FSTAUD25
git switch -c thema/03-sensoren   # neuen Branch anlegen
# Dateien bearbeiten, dann:
git add .
git commit -m "Sensoren: Grundlagen ergänzt"
git push -u origin thema/03-sensoren

Danach erstellst du auf GitHub den Pull Request. Den neuesten Stand holst du mit git switch main und git pull.

Die Einrichtung für den Admin steht in der README des Repositorys.
